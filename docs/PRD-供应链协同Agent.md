# 供应链协同 Agent · 阶段一产品需求文档

**v0.2 · 评审稿 · 2026-11-17**

## 1. 摘要

面向使用 ERPNext 的智能照明及小家电企业采购经办人员，提供一个对话工作台，用于跟进采购订单、查询库存和核对主数据。用户输入单号、供应商或物料等条件，助手读取授权数据，返回带业务编号和查询范围的结果，供采购人员回查和继续追问。

## 3. 背景

跟进采购时，经办人员需要确认订单状态和收货进度，有时还需要核对物料在指定仓库的现存数量。现有项目已接通工作台和 ERPNext，2026-10-30 的本机服饰演示库验收覆盖了五类样本查询、表格展示和一次多步调查审查，也记录了一次模型超时。目标企业的实际需求覆盖率和节省时间仍需试点验证。[阶段一验收记录][acceptance]

## 4. 目标

让采购经办人员能独立完成常见查询、回查关键字段，并识别空结果、部分结果和失败。以下为**首轮试点的建议门槛**，由业务方在启动前确认。

| 关键结果 | 试点结束时的判定 |
| --- | --- |
| 查询任务有效完成率 ≥ 90% | 用至少 20 个真实代表任务验证。关键字段与同权限 ERPNext 基准一致、说明查询范围、能凭单号或条件回查，三项均满足才计为完成。预期为空或拒绝的用例按对应结果判断。 |
| 查询耗时中位数降低 ≥ 20% | 试点人员用原流程和工作台完成同一组成功任务。从读题计到确认答案，包含追问和回查。 |
| P0 验收用例全部通过 | 覆盖只读边界、仓库范围、分页和失败状态。阻塞用例计为未通过。见[采购查询验收用例][cases]。 |

## 5. 目标用户

首版面向需要日常跟单和库存核查的**采购经办人员**。重点任务是按单号或供应商确认采购订单进度，以及按物料和仓库核查库存。ERP 管理员负责配置和确认数据范围。采购人员继续在 ERPNext 中办理业务操作。

## 6. 价值主张

| 维度 | 采购经办人员 |
| --- | --- |
| 谁 | 负责采购跟单和日常数据核查的经办人员。 |
| 为什么 | 想及时确认订单收货进度和库存情况，手里的线索可能只有单号、供应商名称或物料编码。 |
| 原先怎么做 | 典型流程是打开 ERP 列表或详情页，筛选记录、核对字段，再手工汇总。跨页面核对的频率和耗时待验证。 |
| 如何改进 | 在同一对话里发问和追问。助手查询授权数据，按问题整理字段，并带回查编号及范围。 |
| 之后的结果 | 更快拿到可复核的查询结果，能看出哪些数据已查到、哪些仍需核对。 |
| 替代方案 | ERPNext 自带列表和筛选适合熟悉页面、条件明确的单表查询，手工报表适合固定格式汇总。对话工作台主要服务需要多次筛选和追问的临时调查。 |

采购经办人员用一个对话入口核对订单和库存，并凭原始业务编号回到 ERPNext 复核。

## 7. 解决方案

### 7.1 核心流程

用户提问 → 在对象有歧义且会影响结果时补问 → 查询允许访问的记录 → 返回结论、关键字段和查询范围 → 用户回查或在原会话续问。

例如，用户按单号查收货进度，再按物料和仓库核查现存量。两次查询都可在同一会话完成。若追问该物料是否在这张采购单里，助手说明应查看 ERPNext 的订单明细，因为当前只读取表头。

### 7.2 功能与验收口径

| 优先级 | 功能 | 验收口径 |
| --- | --- | --- |
| P0 | 采购订单跟进 | 按单号、供应商、业务状态或单据状态查询指定公司的表头。结果可核对单号、供应商、日期、币种、总额、收货及开票进度，并区分业务状态与草稿、已提交、已取消。表头查询以公司和 ERP 账号权限为准。 |
| P0 | 仓库与库存 | 仓库和库存限配置的公司及仓库清单。按物料和仓库核对现存、预留、已订购及预计数量，明确数量口径和可核对的库存单位。 |
| P0 | 供应商与物料 | 核对名称、分组、类型或库存单位及停用标记。共享主数据按专用 ERP 账号权限读取。 |
| P0 | 查询范围及异常 | 多行结果用表格展示。单页仍有后续记录时说明覆盖范围，全量结论须有足够数据支撑。区分无匹配、权限拒绝、结果未取全和执行失败。超时时标明部分结果与未完成项。ERP 业务操作仅允许读取。 |
| P1 | 多步调查与会话延续 | 展示真实进度，允许回看历史和续问。复杂任务可触发结果审查，业务字段仍由 ERPNext 基准复核。 |

### 7.3 技术与权限

工作台通过 FastAPI 接收流式结果，由 Agent 调用独立的 MCP 工具服务访问 ERPNext。工具白名单限制 ERP 操作为查询，服务端配置公司、仓库和专用只读账号。当前会话标识用于本机区分会话，ERP 查询共用固定账号。工作台保存聊天和任务状态，采购业务数据留在 ERPNext。[项目说明][readme] · [查询约定][skill]

### 7.4 假设与待确认问题

- 确认试点公司、仓库、参与岗位、共享主数据可见范围，以及公司级采购订单表头可见范围。
- 确认哪些跟单问题必须看订单行，以及库存数量口径是否足以支持日常核查。
- 核定任务样本、原流程耗时和验收门槛。目标企业的业务效果、全量分页和重复运行稳定性待验证。

## 8. 发布

- **首版**用于本机演示和受控验证，覆盖五类只读查询、文字和表格结果、异常提示及会话续查。
- **试点计划建议**在数据、授权及参与人员就绪后安排约 2 周。第 1 周确认样本和原流程基线，跑通 P0 用例。第 2 周验证真实任务、复测失败项并评审结果。对多人开放前，完成可信登录、会话访问控制和岗位数据授权。
- **后续范围**根据试点结果评估订单行明细。采购单创建、修改、提交与取消、库存调整、定量补货、BOM（物料清单）和 MRP（物料需求计划）均在阶段一范围之外。
