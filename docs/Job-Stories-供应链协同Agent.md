# 供应链协同 Agent · 阶段一工作故事

**v0.1 · 评审稿 · 2026-11-17**

适用于 ERPNext 只读采购工作台。P0 对应首版核心查询与边界，P1 对应调查和会话体验。每条验收标准都可以在工作台观察，业务记录用相同权限的 ERPNext 数据核对。

## JS-01 跟进采购订单和收货进度 · P0

当供应商或同事询问一张采购单的进度，或者我需要筛出一批待跟进的订单时，我想要查到符合条件的订单和当前状态，以便判断应继续跟进哪些单据。

1. 提供准确单号时，结果显示对应单号和供应商。
2. 组合提供供应商、业务状态和单据状态时，每条返回记录均满足给定条件。
3. 订单日期、总额和币种与 ERPNext 表头一致。
4. 业务状态与草稿、已提交、已取消的单据状态分别呈现。
5. 收货和开票进度分别呈现，并与 ERPNext 表头一致。
6. 多条订单用表格呈现，每条保留单号，结果说明所查公司及表头范围。
7. 追问订单里是否含某物料时，回答说明需要核对订单明细。

对应 PQ-01、PQ-02、PQ-05。[采购查询验收用例][cases]

## JS-02 核查指定仓库的库存 · P0

当有人问某个物料在指定仓库还有多少现存库存时，我想要分清实际在库、已预留和预计数量，以便给出可核对的库存答复。

1. 已知物料编码和授权仓库时，查询结果对应指定物料与仓库。
2. 询问可查仓库时，仓库结果限于配置的公司及仓库清单。
3. 答案保留物料编码、仓库名称和库存计量单位，足以回查原记录。
4. 现存、预留、已订购、预计量分别标明，数值与同权限的 ERPNext 记录相符。
5. 当现存量和预计量不同，回答明确指出实际在库对应的数值。
6. 指定范围外仓库时，明确提示授权边界。换为允许的仓库后可继续查。

对应 PQ-04、PQ-09。[采购查询验收用例][cases]

## JS-03 确认供应商与物料身份 · P0

当手上的采购线索只有供应商名称或物料标识时，我想要确认对应的 ERPNext 记录，以便后续查询使用正确的对象。

1. 提供准确供应商标识后，返回对应名称、分组、类型和停用状态。
2. 提供准确物料记录标识后，返回对应编码、名称、分组、库存单位和停用状态。
3. 返回的标识和字段值与同权限的 ERPNext 基准一致。
4. 字段在 ERPNext 中未填写时，按空值展示或说明。
5. 当同名线索无法唯一确定对象且会影响结论时，询问可用于缩小范围的条件。
6. 说明共享主数据的可见范围取决于专用 ERP 账号权限。

对应 PQ-03、PQ-07。PQ-07 在现有用例中为 P1。[采购查询验收用例][cases]

## JS-04 判断查询结果覆盖了哪些记录 · P0

当我准备引用一批查询结果汇报采购情况时，我想要知道查了哪些记录、还有多少范围待核对，以便判断能否用这些结果下结论。

1. 汇总中说明本次使用的筛选条件及公司或仓库范围。
2. 部分结果以表格呈现，并保留能复核对应记录的标识。
3. 当返回结果还有下一页时，回答明确说明当前仅覆盖已读记录。
4. 能按原筛选条件继续读取后续页，已读范围随查询进展更新。
5. 请求全量总数或汇总时，仅在取全所需记录后给出全量结论。取数中断时标明已覆盖的范围。
6. 用已知总量的跨页样本核对，成功取全后的条数与相同权限和筛选条件下的 ERPNext 基准一致。

对应 PQ-06。全量分页仍属于待验证能力。[采购查询验收用例][cases]

## JS-05 分清空结果、权限受限和失败 · P0

当查询没有得到预期的记录或只完成一部分时，我想要知道原因和已获得的结果，以便决定改条件、确认权限还是重试。

1. 查询成功但无匹配记录时，说明已使用的条件和无匹配结果。
2. 查询被明确拒绝时，说明对应授权边界，回答中不出现越权记录。
3. 查询失败或超时时，页面给出失败状态，说明哪些查询仍未完成。
4. 有已完成的子查询时，保留其可复核记录并标为部分结果。
5. 已查到的结果和未核对的结论分别说明，未完成待办保留实际状态。
6. 用户补充条件或只重查失败项时，工作台能发起下一次查询并返回本次状态。

对应 PQ-08、PQ-09、PQ-11。[采购查询验收用例][cases]

## JS-06 核对记录后继续办理业务 · P0

当我发现订单信息需要修改，或希望调整库存时，我想要先核对当前记录并知道去哪里办理，以便在既有 ERP 流程中完成后续动作。

1. 对明确的修改、提交、取消、创建订单或调整库存请求，说明当前工作台只提供查询。
2. 同一请求包含可授权查询和修改时，可返回查询结果，并明确说明修改请求未执行。
3. 查询结果保留业务编号或物料与仓库标识，便于转到 ERPNext 继续处理。
4. 在隔离验收环境中核对，写操作请求前后对应 ERPNext 业务记录一致。
5. 使用不同措辞 再次提出同一写操作时，只读边界仍适用。
6. 回答明确指向由有权限的人员在 ERPNext 办理的后续步骤。

对应 PQ-10。[采购查询验收用例][cases]

## JS-07 恢复多步骤采购调查 · P1

当采购调查需要先查订单再查库存，或者我中途离开工作台时，我想要看清已完成的步骤和当前结果，以便从原来的问题继续追查。

1. 调查执行时可见步骤和状态，已完成的步骤与实际执行结果相符。
2. 订单与库存结果分别带回查标识，回答说明各自查询条件。
3. 按需触发结果审查时，可见审查状态。最终字段仍可与 ERPNext 原值核对。
4. 刷新页面或从历史打开同一会话，可看到已保存的提问、结果和实际任务状态。
5. 在同一会话追问时，可沿用已明确的单号或物料。新增条件生效时，答案说明新的查询范围。
6. 在窄窗查看既有调查结果时，仍能读到关键信息并访问会话续问入口。

对应 PQ-05、PQ-12、PQ-13。[采购查询验收用例][cases]
