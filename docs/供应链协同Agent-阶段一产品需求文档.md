## 0. 产品概览

| 项目 | 定义 |
| --- | --- |
| 产品定位 | 面向智能照明及小家电企业采购团队的 ERPNext 只读助手。采购人员用自然语言发起调查，在同一对话中查看数据和核对结论。 |
| 用户与任务 | 主要用户拟为采购经办人员。他们需要在跟单和日常核查中确认供应商、物料、仓库库存及采购单状态。具体岗位和使用频率待确认。 |
| 最小业务闭环 | 提出业务问题 → 明确查询对象和范围 → 读取 ERPNext → 查看带查询范围的结果 → 核对结果或继续追问。 |
| 阶段一范围 | 本机工作台，涵盖五类只读查询、基于查询结果的文字与表格整理、复杂任务进度和结果审查、会话历史。 |
| 首要假设 | 在现有字段和数据权限内，采购人员能通过对话完成一部分日常查找与核对。需要用目标企业的实际任务验证。 |
| 首要待决项 | 正式试点使用哪个公司的数据、开放哪些仓库、哪些岗位可以看到这些数据。 |

本稿依据当前项目和已有验收记录整理。功能状态以现有实现为准，岗位分工、使用场景优先级和验收指标是待确认的产品定义。[项目说明](../README.md) · [阶段一验收记录](PHASE1_ACCEPTANCE.md)

## 1. 业务场景与核心问题

采购人员在跟单或核查库存时，需要先确认物料编码、仓库或单据，再核对库存量、订单状态和收货进度。**业务假设**是，当一次核查涉及多个 ERP 页面或多条记录时，查找和汇总会占用时间，单页结果或不同库存口径也容易被误读。目标企业的实际操作耗时和出错频率待试点采集。

| 参与方 | 在流程中的职责 |
| --- | --- |
| 采购人员 | 提出问题，补充物料、仓库、供应商或单号等必要条件，核对结果并决定下一步业务动作。 |
| ERP 数据管理员 | 确认接入公司、仓库和专用只读账号的授权范围，处理权限或数据配置问题。该职责由谁承担，待试点确认。 |
| Agent（智能助手） | 根据问题查询允许读取的数据，说明查询范围和结果限制，整理成便于核对的回答。 |

示例场景是采购人员询问某个物料在指定仓库还有多少现存库存，并追问某家供应商的采购订单收货进度。助手分别查询库存和订单表头。若要确认该物料是否在某一张订单里，助手应说明当前只能看到订单表头，由采购人员到 ERPNext 核对商品明细。

## 2. 产品目标与范围

- 采购人员能从一个对话入口完成常用查询，拿到可凭物料编码、仓库名称或采购单号回查的结果。
- 采购人员能判断结论覆盖哪些数据，区分查无结果、无权访问、查询失败和结果尚未取全。
- 助手的业务操作权限限于读取 ERPNext。需要创建、修改、提交或取消采购订单，或者调整库存时，由有权限的人员在既有 ERP 流程中办理。助手可以保存自己的会话和任务状态。
- 阶段一的分析以现有数据的文字和表格归纳为限。供应商报价与评级、采购订单明细、定量补货和预测分析属于后续范围决策。联网搜索、图表与文件生成、技能安装及命令执行在阶段一入口关闭。

## 3. 核心使用流程

1. **提问与确认条件。** 用户在工作台输入问题。对象不明确或不同解释会改变结果时，助手询问必要条件。用户可选择的查询范围以管理员配置和 ERP 权限为限。
2. **查询和核对范围。** 助手读取所需数据。涉及全量统计时，应查询到足以支持结论的范围；只取得一部分时，说明已读范围、是否还有更多和结论限制。
3. **给出结果。** 用简短文字回答核心问题，多行记录用表格组织，保留相关业务编号、单位、金额币种和查询范围。把 ERP 记录与基于记录的分析判断说明清楚。
4. **处理异常并继续。** 没有匹配记录时，说明已用的条件。权限拒绝时，说明可访问边界。查询失败或超时时，提示未完成以及可继续查询的部分。用户可以回看历史并在同一会话追问。

多步调查可显示待办和当前进度，并按需审查结果。出现未完成或审查未通过时，应如实提示；业务结论是否足以支撑下一步操作，由采购人员判断。

## 4. 首版功能需求

以下优先级为本稿建议。P0 是阶段一查询闭环的验收项，P1 是复杂调查和持续使用的配套能力。

| 优先级 | 能力 | 用户可见结果与业务边界 |
| --- | --- | --- |
| P0 | 供应商查询 | 查看供应商名称、分组、类型和停用状态。供应商属于共享主数据，遵循专用 ERP 账号的读取权限。 |
| P0 | 物料查询 | 查看物料编码、名称、分组、库存单位及停用状态。物料同样属于共享主数据。 |
| P0 | 仓库与库存查询 | 查授权公司和仓库清单内的记录，按物料和仓库核对库存。将现存实物数量、预留量、已订购量和包含计划因素的预计量分别标明。 |
| P0 | 采购订单跟进 | 查指定公司的采购订单表头，核对单号、供应商、日期、业务状态、总额与币种、收货和开票进度。区分业务状态与草稿、已提交、已取消的单据状态。仓库约束适用于仓库和库存，采购订单表头当前没有订单行仓库校验。 |
| P0 | 只读权限与结果说明 | 对越界仓库或数据权限不足给出明确提示。对要求变更 ERP 的指令说明当前操作范围。空结果、结果不完整和执行失败分别提示。 |
| P1 | 多步调查与会话延续 | 可查看查询进度和结果，复杂任务可触发结果审查。用户能回看历史和继续追问，待办状态以实际执行进度为准。 |

当前工作台使用固定的 ERP 专用只读账号，聊天中的本地用户标识仅用于区分会话。面向多人开放前，需要可信登录、会话访问授权和岗位对应的数据权限。[当前业务能力](../README.md#1-当前能力与业务边界) · [只读查询业务约定](../src/skills/erpnext/read-procurement/SKILL.md) · [阶段一验收记录](PHASE1_ACCEPTANCE.md)

## 5. 验收与待确认事项

**主指标建议**是目标企业代表性查询任务的有效完成率，即有效完成的任务数占全部试点任务的比例。一个任务计为有效完成，需同时满足三个条件。关键结果与相同授权范围内的 ERPNext 记录一致。结论与已读取的范围相符。用户能凭返回的业务编号或查询条件复核结果。对于预期拒绝或查无记录的用例，以助手正确识别和说明为通过。

| 检查项 | 通过条件 |
| --- | --- |
| 记录与口径 | 五类查询分别抽样和 ERPNext 对照。重点核对库存数量与单位、采购单状态、总额与币种、收货和开票进度。 |
| 范围与只读 | 对授权仓库能正常查询，对范围外仓库明确拒绝。要求写入、提交、取消或调整库存时，ERP 业务记录保持原状。 |
| 不完整与失败 | 分页样本明确说明覆盖范围。无匹配、越界、查询失败能区分。发生中断或超时时，已有结果标明为部分结果，未完成待办如实呈现。 |
| 业务效率 | 让试点人员分别用原业务方式和助手完成同一组任务，记录耗时、额外追问次数和错误结果。首轮结果用于建立基线，达标阈值待业务方确认。 |

**已有验证**为 2026-10-30 本机服饰演示库的真实只读端到端验收，覆盖五类样本查询、页面展示及一次复杂任务的独立审查。验收记录也保留了一次复杂任务超时。正式目标企业、全量分页和稳定性仍待验证。本次编写未重跑连通性或业务验收。[阶段一验收记录](PHASE1_ACCEPTANCE.md)

**试点前待确认**

1. **试点对象和权限。** 确认使用公司、仓库清单、参与岗位，以及供应商和物料共享主数据的可见范围。
2. **代表任务和通过标准。** 确认首批真实采购问题与对照记录，优先验证库存核查和采购单跟进是否足够覆盖日常需求。
3. **下一阶段范围。** 根据试点结果决定是否优先补订单行、逐人授权或其他能力。若未来开放采购草稿、提交或取消，需单独定义操作权限、人工确认和业务留痕。
